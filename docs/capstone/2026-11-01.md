# LinkGuard capstone progress — 1 November 2026

Today we corrected the research audit, compared new URL-model ensembles on
PhreshPhish, and retrained LightGBM, XGBoost and Random Forest using only the
[ealvaradob dataset](https://huggingface.co/datasets/ealvaradob/phishing-dataset).
We removed invalid/duplicate/conflicting URLs and separated registrable domains
across fitting, calibration, validation and testing. Thresholds were selected
from validation. The audit uses 1,000 domain-bootstrap resamples, separates raw
and system-score AUCs, and leaves undefined single-class metrics blank.

**Ealvaradob-only:** 811,472 cleaned URLs; 178,918 test URLs from 71,527 domains.
At thresholds maximizing validation F1:

| Model | Accuracy | Precision | Phishing recall | F1 | False-positive rate |
|---|---:|---:|---:|---:|---:|
| LightGBM | 88.31% | 83.33% | 92.60% | 87.72% | 15.21% |
| XGBoost | 89.07% | 84.92% | 92.13% | 88.37% | 13.44% |
| Random Forest | 88.79% | 85.00% | 91.23% | 88.01% | 13.22% |

**PhreshPhish:** on the same 80,693 domains-unseen test URLs, existing XGBoost
had 58.37% accuracy / 39.94% recall / 2.95% false positives. The new conservative
ensemble achieved 85.21% / 79.36% / 2.49%; the balanced ensemble achieved
91.24% / 93.58% / 13.67%. This improves detection but does not establish 95%
across all metrics. High phishing prevalence inflates precision relative to
ordinary browsing. URL/domain separation does not prove campaign separation.
The strictly later-collected unseen-domain subset contains 84,725 URLs.

**Corrected existing-model audit:** combined held-out accuracy 84.98% and
phishing recall 66.72%; Kaggle unseen-domain accuracy 93.82% and malicious
recall 89.47%. Kaggle positives largely represent URLhaus malware; OpenPhish-only
recall was 38.87%, so malicious recall must not be presented as phishing recall.

**Outcome:** all 35 backend tests passed. Research code and regression tests are
retained; production models and serving behavior are unchanged. Disposable
experiment caches, candidate binaries, per-URL predictions and duplicate reports
were recycled. A new untouched cohort and broader benign deep-link coverage,
plus independently evaluated page-content/brand/reputation signals, are needed
before stronger real-world claims or deployment.

The single retained results file is
[linkguard_final_results_2026-11-01.csv](linkguard_final_results_2026-11-01.csv).
Metrics use fractions (0.90 = 90%); blank means undefined/unavailable. Historical,
corrected-audit and final-test cohorts are explicitly separated and should not
be ranked across datasets. `selected_on_validation` identifies the preselected
PhreshPhish candidates. Historical rows preserve earlier development scores.

Reusable entry points: `backend/research_audit.py`, `backend/research_v3.py`,
`backend/research_report.py` and `backend/research_single_dataset.py` (`--help`).
The PhreshPhish workflow acquires train metadata with `research_data.py --split
train`, freezes candidates with `research_v3.py --stage train`, then acquires
test metadata and runs `--stage test` once, using a new `--output` directory.
The Parquet reader needs optional `pyarrow`; serving requirements are unchanged.

## Later phishing-specific audit and improvement

A second, frozen experiment reserved new OpenPhish and PhishTank snapshots.
On the same 48,406 URLs from domains unseen by both systems, a 25% XGBoost /
75% character-model candidate improved phishing recall **55.80% → 76.34%**, F1
**68.91% → 85.08%**, and FPR **3.07% → 1.55%**. Fresh OpenPhish recall improved
**67.42% → 83.90%**. These are new cohorts, not replacements for the earlier scores.
The candidate failed the predeclared 1% FPR gate; the original production model
remains selected. Its compact 1.31 MiB artifact and reproducibility evidence are
retained privately. The API received a decision-rounding fix and structured rule
evidence. **45 backend tests and 7 browser tests passed**, with mobile and
accessibility checks. See [the evaluation report](../EVALUATION_REPORT.md) and
[capstone alignment](../CAPSTONE_ALIGNMENT.md) for details and limitations.

The API patch was subsequently **redeployed successfully to Render at 19:52 IST**.
All 7 browser tests passed against the live Vercel/Render application, and ten
Kaggle samples matched deployed predictions. The existing XGBoost model remains
active; [final deployed scores](../DEPLOYMENT_STATUS.md) distinguish malware
recall from phishing recall. The research ensemble was not promoted.
